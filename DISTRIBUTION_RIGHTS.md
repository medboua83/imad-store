# Droits à joindre à une livraison commerciale

Le code spécifique n'est pas publié sous MIT ou une autre licence libre générale. Le fichier `LICENSE` réserve les droits existants ; il n'accorde pas automatiquement de nouveaux droits à un acheteur et ne prétend pas attribuer les contributions d'un tiers au vendeur. Un dépôt public peut être consulté et forké selon les conditions de GitHub, sans que cela suffise à établir un droit général de redistribution : [documentation GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).

Avant une vente, le titulaire réel ou son représentant habilité doit compléter et signer l'accord de livraison. Choisir explicitement entre une licence d'exploitation et une cession ; ne pas confondre l'installation du logiciel, le droit de l'utiliser et le droit de revendre son code. Le modèle de remise est dans `docs/CLIENT_HANDOVER.md`.

L'accord doit identifier les parties, le commit livré, les installations autorisées, les droits de modification et de redistribution, le prix, les éléments exclus, la maintenance et ses limites. Aucun délai de disponibilité ou de reprise ne doit être promis à partir d'un seul essai local. Une sauvegarde conditionnée à un Mac allumé et un disque connecté ne constitue pas une infrastructure indépendante disponible en permanence.

Les licences des dépendances restent applicables. Conserver leurs notices avec les dépendances réinstallées et consulter `THIRD_PARTY_NOTICES.md`. L'inventaire fourni n'est pas une certification de provenance de toutes les contributions historiques.

Les photos, logos, thèmes de marque et données d'IMAD ne sont pas inclus dans une autorisation générale. Les images de test et les images présentes dans le code doivent être remplacées ou leur droit de réutilisation établi par le marchand. Les données réelles, sauvegardes et profils privés ne sont jamais un jeu de démonstration pour un nouveau client.
