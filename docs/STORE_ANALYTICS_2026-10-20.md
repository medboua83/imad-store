# Store visitor statistics

The admin Statistics tab shows rolling 7/30/90-day visits, product consultations, the top 20 products, and conversion. A visit is an approximate browser-tab session with a maximum duration of 30 minutes. Each allowlisted path/product is counted once per visit. Query strings, referrers, customer details, IP addresses and browser fingerprints are not included in analytics records. Visits are not unique people across devices or tabs.

Conversion is **measured visits with at least one server-created order / measured visits**. It is not payment or confirmation rate. Several orders in one visit do not raise the rate above 100%. Order retries are deduplicated by a digest of the committed order ID. Attribution requires a preceding measured visit within 30 minutes; historical orders are not backfilled. Browser privacy exclusions, blocked requests and expired visits can leave orders unattributed. An attribution failure never rolls back or rejects an already committed order. Idempotent order replay may repair a failed attribution while still inside the same attribution window.

The browser keeps only a random identifier and its start time in sessionStorage. The server stores a digest scoped to the installation. Admin-token sessions, DNT/GPC, recognized bots and explicit `stats_test=1` events are excluded. Ordinary localhost/loopback visits are skipped unless test mode is explicitly enabled. Test mode stays on the ephemeral visit and its order headers; it does not enter production summaries. This is a lightweight first-party measurement tool, not fraud-resistant audited traffic attribution. Retention uses a MongoDB TTL index at 91 days, subject to MongoDB's asynchronous expiration cycle. The privacy page explains the measurement even when custom policy text is published.

One company per deployment/database remains the installation contract. The analytics scope comes only from validated server STORE_INSTANCE_ID and CRM_COMPANY_ID, or the existing isolated legacy database; it cannot be supplied by a request. Admin summaries require the existing administrator token and use private/no-store responses. A copied analytics-only database cannot be rebound as a fresh company. No new security keys or third-party analytics account are needed.

The additional MongoDB collection is created lazily, with bounded queries and scoped/time/session indexes. No Prisma schema change or live db push is needed. Public event input is strict, same-origin checked and rate limited. The dashboard module loads only when opened; no chart library or external tracking script is added.

Validation: 44 integration/client tests, including concurrent duplicate views, fake conversion rejection, exclusions, UUID expiry, genuine committed order retries, several orders per visit, attribution failure preserving checkout, period filtering and scope separation. Combined-hosting tests pass in TCP, Passenger and LiteSpeed modes. Browser test uses a new disposable local database with no CRM delivery: one visit + one product consultation + one real local fictitious order produce 100%; desktop, period changes and mobile navigation are checked separately. Publication evidence is recorded outside the repository after deployment. No production order or client message is required by this release.

Rollback: revert the release code. Existing commerce data and CRM configuration are unchanged. The dormant analytics collection may expire by its TTL; do not delete the active commerce database.
